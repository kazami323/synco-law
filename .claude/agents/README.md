# Агенты проекта

Специализированные субагенты для AI Legal Workspace. Каждый заточен под свою
зону ТЗ и под конкретные грабли этого проекта, а не «универсальный ревьюер».

Каноническое ТЗ — [docs/FUNCTIONAL_SPEC.md](../../docs/FUNCTIONAL_SPEC.md).
Текущие расхождения — [docs/SPEC_GAP_ANALYSIS.md](../../docs/SPEC_GAP_ANALYSIS.md).

## Кто есть кто

### Проверяющие (не пишут код)

| Агент | Зона | Когда звать |
|---|---|---|
| **spec-auditor** | соответствие ТЗ | после любой продуктовой доработки, перед сдачей вехи, вопрос «что осталось по разделу N» |
| **legal-domain-reviewer** | право Узбекистана, lex.uz, вердикты, дисклеймеры | изменения в `agents/`, `services/legal_*`, промптах, текстах для юриста |
| **security-reviewer** | изоляция организаций, авторизация, загрузки, секреты | перед релизом, изменения в auth/permissions/upload/deploy |
| **backend-reviewer** | FastAPI, SQLAlchemy async, миграции, схемы | после изменений в `backend/` |
| **frontend-reviewer** | Next.js 16, LexOS, UX юриста | после изменений в `frontend/` |

### Исполнители (пишут код)

| Агент | Зона |
|---|---|
| **clause-engine-dev** | разделы 4 ТЗ: разбивка на пункты, Модули 1–3, подтверждение юристом |
| **docflow-dev** | разделы 2, 3, 5, 6 ТЗ: статусы, создание документа, шаблоны, версии, экспорт |
| **prompt-engineer** | промпты AI-агентов и их JSON-контракты |
| **test-engineer** | pytest, Playwright, прогон CI локально |

## Как пользоваться

Агенты запускаются **по явной просьбе**. Например:

- «проверь эту работу spec-auditor и security-reviewer»
- «пусть clause-engine-dev сделает разбивку документа на пункты»
- «прогони test-engineer по новому коду»

Разумные связки:

| Что сделали | Кого звать |
|---|---|
| фича по Модулям 1–3 | `spec-auditor` → `legal-domain-reviewer` → `backend-reviewer` |
| изменение статусов или прав | `security-reviewer` + `spec-auditor` |
| правка промпта | `legal-domain-reviewer` + `test-engineer` |
| экран для юриста | `frontend-reviewer` + `spec-auditor` |
| подготовка к релизу | `security-reviewer` → `test-engineer` → `spec-auditor` |

Проверяющих можно запускать параллельно — они читают, но не пишут.
Исполнителей по одной зоне — по очереди, чтобы не конфликтовали правки.

## Правила для всех агентов

1. ТЗ — источник истины. Расхождение = дефект, если не записано в gap-анализе.
2. AI только предлагает; решение юриста фиксируется с автором и временем.
3. Любой запрос к данным фильтруется по `organization_id`.
4. Изменил модель — сделай миграцию в том же изменении.
5. Отчитывайся фактами: реальный вывод тестов, честно про недоделанное.
