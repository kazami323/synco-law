# Правовой движок — функциональное описание

> Источник: ТЗ заказчика (PDF «Правовой движок — функциональное описание»).
> Это **каноническое ТЗ продукта**. Любое расхождение кода с этим документом —
> дефект, если оно не зафиксировано явно в [SPEC_GAP_ANALYSIS.md](SPEC_GAP_ANALYSIS.md)
> как осознанное отложенное решение.

Система для юридического отдела: создание, проверка и утверждение договоров
с опорой на правовую базу.

---

## 1. Структура системы

```text
Рабочее пространство
└── Проект (сделка / клиент / направление)
    ├── Документ 1
    ├── Документ 2
    └── Документ N
```

**Проект** — контейнер под конкретную задачу: сделку, клиента, направление
работы. Содержит несколько связанных документов, общий контекст (стороны,
суммы, сроки), участников с правами доступа.

**Документ** — единица работы. Имеет тип, статус, версии, историю изменений
и результаты проверок.

---

## 2. Статусы документа

| Статус | Что означает | Кто ставит |
|---|---|---|
| **Черновик** | Документ создан, работа не начата | Система |
| **Сгенерирован** | ИИ создал текст, проверки не проводились | Система |
| **На проверке** | Запущены модули анализа | Система |
| **Проверен** | Все три модуля отработали, замечания выведены | Система |
| **Подтверждён юристом** | Юрист прошёл по замечаниям и утвердил | Юрист |
| **На доработке** | Возвращён после замечаний | Юрист / руководитель |
| **Финальный** | Готов к подписанию, редактирование заблокировано | Руководитель отдела |
| **В архиве** | Работа завершена | Юрист |

Переход между статусами фиксируется в журнале: кто, когда, комментарий.

---

## 3. Создание документа

Юрист выбирает один из трёх сценариев.

### 3.1. Генерация с нуля

**Шаг 1 — тип документа.** Выбор из каталога: договор поставки, оказания
услуг, подряда, аренды, купли-продажи, трудовой, NDA, лицензионный,
доп. соглашение и т. д. Тип определяет, какие блоки будут обязательными и
какие нормы подтягиваются для сверки.

**Шаг 2 — шаблон (опционально).** Выбор шаблона из базы. Шаблоны хранятся с
метаданными: тип, кем создан, дата актуализации, отметка о верификации. Без
шаблона документ генерируется по общей структуре, принятой для этого типа.

**Шаг 3 — постановка задачи.** Голосовой или текстовый ввод условий:

> «Договор поставки, поставщик — ООО, покупатель — ИП, товар — оборудование,
> предоплата 30%, отсрочка 60 дней, штраф за просрочку 0,1% в день,
> подсудность — Ташкент.»

Аудио расшифровывается, из речи вытягиваются параметры (стороны, суммы,
сроки, санкции) и показываются юристу карточкой для подтверждения перед
генерацией. Юрист может дополнить или поправить любое поле.

**Шаг 4 — генерация.** Документ собирается на основе шаблона + условий +
релевантных норм. Статус: **Сгенерирован**.

### 3.2. Загрузка готового документа

Загрузка DOCX / PDF (в т. ч. скан с распознаванием). Система разбирает текст
в структуру и переводит документ сразу в очередь проверки. Сценарий для
входящих договоров от контрагентов.

### 3.3. Создание из существующего

Копия любого документа проекта как основа для нового — для однотипных
договоров с разными сторонами.

---

## 4. Модули проверки

После генерации или загрузки доступны три модуля. Запускаются по отдельности
или все сразу.

### Модуль 1. Разбивка на пункты и сверка с правовой базой

**Разбивка.** Документ автоматически делится на структурные единицы:
разделы → пункты → подпункты. Каждый пункт получает свой идентификатор и
становится отдельным объектом для работы.

**Сверка.** По каждому пункту система:

- определяет, какие нормы законодательства его регулируют;
- находит соответствующие статьи в базе и приводит их текст;
- выносит вердикт: **соответствует** / **противоречит** / **требует внимания** /
  **норма не найдена**;
- при противоречии — указывает конкретную статью и предлагает
  формулировку-замену.

**Подтверждение юристом.** Интерфейс работы «пункт за пунктом»: слева текст
пункта, справа найденные нормы и вердикт системы. По каждому пункту юрист
выбирает:

- **Подтвердить** — пункт принят как есть
- **Изменить** — правка текста вручную или принятие предложенной формулировки
- **Комментарий** — заметка для коллеги или для себя
- **Отложить** — вернуться позже

Прогресс отображается счётчиком (например, 14 из 23 пунктов подтверждено).
Пока не подтверждены все пункты, документ не может перейти в статус
**Подтверждён юристом**.

> **Важно:** система только предлагает. Финальное решение по каждому пункту —
> за юристом, и оно фиксируется с указанием автора и времени.

### Модуль 2. Сверка логики между пунктами

Проверяет документ как единое целое — на внутреннюю непротиворечивость:

- **Противоречия по срокам** — в одном пункте оплата 30 дней, в другом 45
- **Противоречия по суммам** — цифры в тексте, в приложении и в реквизитах расходятся
- **Битые перекрёстные ссылки** — «в соответствии с п. 5.4», а такого пункта нет
- **Неопределённые термины** — термин используется, но не раскрыт в разделе определений
- **Дублирование** — одно и то же условие описано дважды по-разному
- **Разрывы в цепочках** — прописан порядок расторжения, но нет порядка уведомления
- **Несогласованность сторон** — в тексте «Заказчик», в шапке «Клиент»

Каждое расхождение выводится с указанием **обоих конфликтующих пунктов рядом**,
чтобы юрист видел суть за секунду. Действия: принять правку, отклонить,
поправить вручную.

### Модуль 3. Сверка на смысл и риски

Оценка договора с позиции защищённости стороны.

**Настройка перед запуском:** юрист указывает, **чью сторону представляет** —
это меняет всю оптику анализа.

Что выявляется:

| Категория | Примеры |
|---|---|
| **Асимметрия условий** | Штрафы только для одной стороны; право расторжения в одностороннем порядке только у контрагента |
| **Пробелы** | Не описан форс-мажор, порядок приёмки, механизм разрешения споров, ответственность за качество |
| **Размытые формулировки** | «в разумный срок», «надлежащее качество», «по согласованию» — без критериев |
| **Финансовые риски** | Отсутствие потолка ответственности, автопролонгация с индексацией цены, скрытые обязательства |
| **Операционные риски** | Нереалистичные сроки, зависимость от третьих лиц без оговорок |
| **Риски исполнения** | Отсутствие обеспечения, слабые механизмы взыскания |

**Вывод:** каждый риск с уровнем (высокий / средний / низкий), объяснением
последствий на практике и предложением по устранению. Плюс сводная оценка
документа и краткое резюме — что критично поправить до подписания.

---

## 5. Работа с результатами

**Сводка по документу** — единая панель: сколько пунктов проверено, сколько
замечаний по каждому модулю, сколько устранено, что осталось.

**Версионирование** — каждая правка создаёт версию. Сравнение любых двух
версий в режиме различий. Откат к предыдущей.

**Экспорт** — DOCX и PDF. Опционально: чистая версия для контрагента и
рабочая версия с комментариями и замечаниями для внутреннего использования.

**Журнал действий** — полная история: кто создал, кто что подтвердил, когда,
с каким комментарием. Нужен и для внутреннего контроля, и для разбора
спорных ситуаций постфактум.

---

## 6. База шаблонов

Отдельный раздел системы:

- шаблоны по типам документов;
- статус актуальности (дата последней проверки на соответствие законодательству);
- отметка «верифицирован» с указанием юриста;
- возможность сохранить любой подтверждённый документ как новый шаблон;
- уведомление, если законодательство изменилось и шаблон затронут.

---

## 7. Роли и права

| Роль | Возможности |
|---|---|
| **Юрист** | Создание проектов и документов, запуск проверок, подтверждение пунктов, экспорт |
| **Старший юрист / руководитель** | Всё выше + перевод в статус «Финальный», верификация шаблонов, доступ ко всем проектам |
| **Наблюдатель** | Просмотр и комментирование без права изменения статусов |
| **Администратор** | Управление пользователями, правовой базой, каталогом типов документов |

---

## 8. Правовая база

Фоновый слой, обеспечивающий работу Модуля 1:

- кодексы и НПА в структурированном виде (по статьям);
- судебная практика (опционально, для оценки рисков);
- механизм обновления при изменении законодательства;
- при каждой ссылке — **редакция нормы на дату проверки**, чтобы результаты
  были воспроизводимы.
